## Decisions

- **Writer is write-through with an outbox fallback.** `audit.record` inserts directly (or
  inside `tx`); if the insert fails, it appends the row to
  `storage/audit-outbox/<pid>.jsonl` with `fsync`; a flusher inserts outbox rows at boot
  and every 30 s. Only when both fail does a `must_record` action throw; other actions
  increment the `write_failed` counter. The parent plan says "appends to an outbox, then a
  flusher inserts"; write-through keeps rows visible immediately and is equally durable.
- **Context is resolved lazily.** `auditContext` middleware puts `{request_id, ip,
  user_agent, channel}` in `response.locals.audit` and an `AsyncLocalStorage` store; the
  actor is read at record time from `response.locals` (user, apiKey, device, embedConfig),
  because the auth middleware runs after the context middleware.
- **`EventLogs.logEvent` becomes a wrapper** that maps legacy event names to catalogue
  actions (`LEGACY_EVENT_MAP`) and calls `audit.record`. The existing Event Logs page reads
  `audit_events` through `EventLogs.whereWithData` and `count`, mapped back to the old shape,
  so it shows new and copied rows. `EventLogs.delete` and the delete route are untouched in
  PR A (PR B removes them).
- **Migration** creates `audit_events` (with nullable `prev_hash`/`hash` for PR B) and copies
  `event_logs` rows as `action = 'legacy.' || event`, `actor_type = user|unknown`,
  `channel = 'unknown'`.
- **must_record without a transaction** records after the action and fails the request with
  500 if neither the database nor the outbox accepts the row. Views of other users' chats
  record before the data is returned, so a failed write blocks the view (acceptance 3).
  Transactions are used where the model already takes one; new AP/GS code uses `tx`.
- **Route coverage** is a static test: a fake `app` captures every route registered by every
  `*Endpoints` function; each state-changing route must be in `server/utils/audit/routes.js`
  with its actions (each must exist in the catalogue and appear as a string literal in the
  handler source or a named file), or exempt with a reason.
- **Backstop** is a `$use` middleware on the shared client: writes to the sensitive tables
  are collected in the request's store; at response finish (or job end), tables with no
  catalogue event covering them get one `db.write` row.
- **Outbound inventory** wraps the provider classes' exported constructors via a registry
  (`server/utils/audit/vendors.js`) that maps every class under `AiProviders`,
  `EmbeddingEngines`, `vectorDbProviders`, `TextToSpeech`, `SpeechToText`,
  `ImageGenerators` and web search to a vendor id, and counts calls per vendor, workspace
  and hour into `vendor.data_sent`. The test lists the provider folders and fails on a
  class without a registry entry. HIPAA-mode refusal waits for the BAA register (CH).
